# 디지털 트윈 그래픽 개선 기록

2026-10-17 · 개발 전달 최종안 기준. 작업 전부터 있던 자연 어항 배경, 장식 앞뒤 레이어, 기포 수정과 계정·색상·액세서리 기능을 유지하면서 물고기 렌더링과 추적 입력 처리를 추가했다. 기존 작업 중인 변경은 되돌리지 않았다.

## 구현

- 한 장의 원본 PNG를 48×32 평면 격자에 표시하고 꼬리·등·아래 지느러미의 정점만 움직인다. 몸통 보호, 꼬리 뿌리·부착선 고정, 부드러운 영역 경계와 겹침 가중치 제한을 적용한다. 전체 이미지 크기를 반복 변경하던 방식과 8방향 이미지 교체를 제거했다.
- 기본 PNG의 실제 외형을 확인하고 `public/fish_sprites/fish_right.rig.json`에 부위를 지정했다. 사용자 그래픽에는 임의의 물고기 부위를 자동 적용하지 않는다. 설정이 없으면 원본 이미지로 표시한다.
- 개인 설정의 저장 그래픽마다 **움직임 설정** 버튼을 추가했다. 체크무늬 위에서 몸통·지느러미 영역을 그리거나 이동·크기 조절하고, 뿌리와 부착선을 드래그하거나 Tab·방향키로 조정할 수 있다. 원본 머리 방향, 부위 생략, 강도와 기본/빠른 수영 미리보기를 제공한다. 저장 실패와 취소는 기존 설정을 유지한다.
- `GET /api/fish/graphics/:id/rig`, `PUT /api/fish/graphics/:id/rig`, 현재 선택용 `GET /api/fish/rig`를 추가했다. 세션 사용자 소유권, 버전, 좌표·크기·강도와 요청 크기를 검증한다. 서버가 원본 PNG 바이트의 SHA-256과 크기를 비교하고 이미지가 바뀌면 변형을 중단한다.
- Python → 개인 카메라 API와 물리 어항 `/posi`에서 같은 시각화 메시지를 전달한다. 프레임 번호, 세션·대상 ID, 프레임 크기, 탐지·자세 점수, 키포인트와 유실 상태를 보존한다. 누락 좌표를 중앙 측정값으로 만들지 않는다. Python 시각은 **디코딩 후 추론 입력 시각**이며 실제 촬영 시각으로 간주하지 않는다.
- 수신 후 경과시간은 브라우저 단조 시계로 계산한다. 위치와 자세를 독립 검증하고 큰 위치 변화·반대 자세는 연속 관측 후 반영한다. 중복·역순 프레임을 무시하고 세션·대상 변경 시 확인 이력을 초기화한다. 유실 중 마지막 위치·방향과 기본 지느러미 움직임을 유지한다.
- 별도 상태 타이머로 `추적 대기`, `대상 확인 중`, `추적 중`, `자세 확인 중`, `추적 일시 중단`, `연결 확인 필요`를 표시한다. 수신 전 정상 표정이나 무조건 켜지는 LIVE 배지를 표시하지 않는다. 기존 서버 이상행동 판정은 유지하고 화면 경고만 지속·신선도 조건으로 제한한다.
- 개인 카메라가 최근 4.5초 안에 수신되는 동안 물리 카메라가 그 위치를 덮어쓰지 않게 했다. 두 소스가 번갈아 좌표계를 변경하지 않는다. 다른 기기에서도 같은 계정의 개인 카메라 데이터를 받을 수 있다.
- 프레임과 어항의 종횡비 차이는 전체 프레임을 보존하는 contain 배치로 보정한다. 작은 카메라 미리보기도 같은 규칙으로 변경했다.
- WebGL 불가·컨텍스트 유실·설정 없음·이미지 오류 시 이미지 표시를 유지한다. 색상 필터는 물고기만, 액세서리는 반전·회전하는 머리 좌표계에 적용한다. 상태 문구는 전경과 별도 순서로 표시한다. 움직임 줄이기와 자원 정리를 지원한다.

## 적용과 사용

1. Node 서버와 Python AI 서버에 변경 파일을 반영하고 재시작한다. 프론트는 `npm run build` 결과를 사용한다. 이 작업에서는 운영 서버를 재시작하거나 배포하지 않았다.
2. Node 시작 시 기존 `fish_graphics` 테이블을 유지하면서 nullable `rig_json TEXT` 컬럼 하나를 추가한다. 기존 행과 이미지 파일은 변경하지 않는다. 기존 DB는 운영 절차에 따라 백업한 후 적용한다.
3. **개인 설정 → 물고기 그래픽 → 저장된 그래픽의 움직임 설정 → 몸통 보호 → 꼬리·뿌리점 → 필요한 지느러미 → 미리보기 → 이 그래픽에 저장**.
4. 기본 공용 이미지의 사전 설정을 편집해 저장해도 해당 사용자의 그래픽 행에만 반영된다.

## 검증 도구와 결과

- `npm test`: 기존 테스트 및 새 추적·변형·저장 API·두 중계 경로 테스트 통과. API 테스트는 임시 파일과 메모리 DB를 사용한다.
- `npm run build`, `node --check server.cjs`, `python3 -m py_compile fish_ai_server.py`, `git diff --check` 통과. Three.js는 동적 로딩한다. 빌드에는 약 505kB 렌더러 청크 크기 경고가 남는다.
- 별도 `npx tsc -p tsconfig.app.json --noEmit`에서는 작업 전부터 있던 `Records.tsx`의 nullable 차트 값·타입 가드 오류와 `TankTheme.tsx`, `PersonalSettings.tsx`의 미사용 변수 오류가 남아 있다. 이번 변경 파일의 새 타입 오류는 해결했으며, 관련 없는 기록 계산 코드는 수정하지 않았다. 현재 프로젝트의 기본 빌드 명령은 이 별도 프로젝트 검사와 같지 않다.
- `scripts/verify-digital-twin.mjs`: Playwright가 설치된 환경에서 `CFT_BASE_URL=http://127.0.0.1:5174 node scripts/verify-digital-twin.mjs`로 실행한다. 필요하면 `CFT_PLAYWRIGHT_MODULE`, `CFT_CHROMIUM`을 지정할 수 있다. API·WebSocket은 모의 응답을 사용하며 운영 계정·DB를 수정하지 않는다.
- Chromium에서 1440×1000, 800×1000, 390×1000 뷰포트를 확인했다. 추적 대기, 정상 입력, 단일 이상치, 유실·수신 중단·세션 복귀, 다른 계정 메시지 무시, 격자 표시, WebGL 컨텍스트 유실 대체, 움직임 줄이기, 편집 키보드 조작, 저장 실패·복원·취소, 설정 없는 이미지 표시와 가로 넘침을 확인했다. 브라우저 실행 오류는 없었다.
- 화면 기록: `dashboard-1440.png`, `dashboard-800.png`, `dashboard-390.png`, `tracking-interrupted-1440.png`, `rig-editor-1440.png`, `rig-editor-390.png`, `tracking-replay.png`.
- 개발 서버의 `/tools/tracking-replay.html`은 동일 입력을 직접 표시한 위치와 안정화 결과를 나란히 재생한다. 기본 입력은 **합성 테스트·데모**로 표시한다. 실제 기록은 `at_ms`가 포함된 시간순 프레임 JSON 배열을 파일로 열어 로컬에서만 재생한다. 별도 개발용 페이지로 일반 앱 메뉴와 프로덕션 빌드에는 포함하지 않는다.

## 조정값과 남은 확인

초기 위치 확인 900ms, 큰 자세 변화와 반전 확인 800ms(같은 관측 구간에서 함께 확인), 위치 이상치 거리 0.22, 정지 노이즈 범위 0.004, 표시 보간 시간상수 300ms를 사용했다. 유실은 관찰한 수신 간격의 3.5배/최소 2.6초, 연결 확인은 6배/최소 4.5초다. 고정 보정값이므로 실제 기록을 보며 조정해야 한다. 외부 송신기의 `stream_id`는 즉각적인 세션 초기화에 필요하고, 동일 좌표계의 `frame_size`는 화면 종횡비 보정에 필요하다. 크기 정보가 없어도 픽셀 좌표로 확인되는 머리·꼬리 벡터와 유효 자세 신뢰도가 있으면 방향은 반영한다. 모호한 0–1 좌표의 종횡비와 없는 프레임 크기를 추정하지 않는다.

실제 어항 영상·AI 출력 묶음과 서로 다른 세 가지 대표 물고기 에셋이 제공되지 않아 실제 오탐 빈도, 장기 가림, 모든 지느러미 형상의 품질을 인수 완료로 판단하지 않는다. 기본 베타 한 장의 영역·연결부와 합성 입력은 확인했다. 실기기 60/30fps, 실제 카메라·센서·운영 DB 연결, 실제 녹화 전후 영상은 후속 확인이 필요하다.

박스 기반 크기·원근, 속도에 따른 실제 애니메이션 변화, 정면/후면 추정은 활성화하지 않았다. 빠른 수영은 편집기의 명시적인 미리보기에서만 제공한다.

## 방향 미반영 수정

실제 물리 어항 WebSocket에서 양수 `pose_conf`와 픽셀 머리·꼬리는 들어오지만 `frame_size`는 `null`인 것을 확인했다. 처음 추가한 검증이 이 입력을 모두 차단했다. 픽셀 벡터 각도 계산에 필요하지 않은 프레임 크기 조건을 해제하고, 크기가 있는 입력의 범위 검증 및 신뢰도 0·모호한 정규화 좌표의 보류는 유지했다. 반전 확인도 자세 확인과 동시에 진행하도록 바꿔 두 차례 대기하지 않게 했다. 프레임 크기가 없는 실제 입력 형태와 안정적인 반전 시간에 대한 회귀 테스트를 추가했다.
