# 디지털 트윈 움직임·깊이·구조물 레이어 구현 결과

2026-10-18 · 요청 문서: `CyberFishTank_트윈화면_움직임_깊이_구조물레이어_개발명세_최종.md`

현재 작업 디렉터리를 기준으로 수정했다. 시작 시 존재하던 모바일·대시보드 변경을 유지했다. 운영 배포 SHA 비교 및 운영 서버 재시작은 수행하지 않았다.

## 반영 내용

- 기존 생성 PNG, 원본 해시 검증, 수동 부위 설정, 연결된 격자 변형과 구형 이미지 대체 표시를 재사용한다.
- 위치의 고정 데드밴드를 없애고, 영상 종횡비를 반영한 벡터 One Euro 안정화와 짧은 표시 보간을 적용했다. 단발성 점프는 보류하고 지속적인 빠른 이동은 확인 후 받아들인다.
- 위치·자세·깊이의 유효성을 분리한다. 중복·역순 프레임, 단조 수신 시각, 샘플 timestamp 차이, 대상·스트림 변경을 처리한다. 서버 epoch와 브라우저 performance 시각을 직접 빼지 않는다.
- 자세 점수와 픽셀 키포인트 길이를 검사하고, 약한 각도 변화와 좌우 전환의 확인 시간을 분리했다. 확인된 전환은 최소 폭 0.78의 짧은 가로 압축과 함께 연결한다. 상태 UI는 반전·확대하지 않는다.
- 박스 높이/영상 높이의 안정 구간 중앙값을 깊이 기준으로 수집한다. 회전·기울임·잘림·높이/몸통 길이 불일치·낮은 탐지 품질·급격한 단발 변화는 보류한다. 안정적인 새 높이가 지속되면 받아들인다.
- 깊이는 중심 좌표를 유지한 균일 배율 0.90~1.10과 약한 대비·채도 변화로 표현한다. 자세가 없으면 0.96~1.04로 제한한다. 메타데이터가 없을 때 위치·기본 지느러미는 계속 표시한다.
- 수초를 자동 추가하지 않고 기존 터널·장식의 좌표와 크기를 유지한다. 뒤쪽 → 중간 → 물고기 → 앞쪽 → 유리 → 상태 UI 순서로 합성한다. 깊이 배율이 장식과의 겹침 순서를 자동으로 바꾸지 않는다.
- 꾸미기에 3단계 레이어, 같은 레이어 안의 앞/뒤 한 칸 이동, 가려진 장식을 고르는 목록, 현재 순서, 저장 중/완료/실패와 최신 배치 재시도를 제공한다. 선택 핸들은 구조물보다 위에 표시한다.
- 새 구조물은 중간 레이어를 사용한다. 기존 back/front/누락값은 그대로 유지한다. 배열 순서를 저장하며 목적 레이어를 바꾼 항목은 해당 레이어 맨 앞으로 이동한다. 장식 추가 ID는 UUID로 생성해 충돌을 피한다.
- 저장 요청을 직렬화하고 계정 로드 완료를 확인한다. 응답 실패를 성공으로 표시하지 않는다. 계정 전환 중 오래된 조회 결과와 다른 계정으로 보내려는 배치 저장을 방어한다.
- 부위 설정 조정 시 같은 이미지의 WebGL 렌더러·텍스처를 유지하고 가중치만 갱신한다. 꼬리·지느러미의 위상을 유지하면서 검증된 정규화 위치 속도를 천천히 반영한다. 키보드와 포인터 이동 모두 뿌리점·부착선을 같이 이동한다.
- `npm run build`가 실제 참조 프로젝트까지 검사하도록 `tsc -b`를 사용한다. 기존 차트에서 측정 숫자와 표시용 빈값을 구분하는 타입을 보완했다. 원본 데이터와 집계 수식은 변경하지 않았다.

## 저장/API 호환성

기존 `decorations_json` 배열을 그대로 사용한다. 데이터베이스 스키마 마이그레이션은 없다.

`layer` 허용값은 `back | middle | front`이며 누락은 기존처럼 back이다. 배열 안에서 뒤 항목이 같은 레이어의 앞에 그려진다. 별도의 zIndex 필드는 없다.

`POST /api/aquarium-decorations`의 기존 형식을 유지하면서 프론트는 선택 필드 `ownerUserId`를 함께 보낸다. 이 값이 로그인 세션과 다르면 409로 거절한다. 구형 클라이언트는 필드를 생략할 수 있다. 잘못된 레이어는 400이며 기존 저장값을 덮어쓰지 않는다. 실행 중인 Node API 서버에는 재시작 후 이 검증과 middle 허용이 적용된다.

## 내부 시작값

| 항목 | 값 |
|---|---|
| 위치 minCutoff / beta / derivativeCutoff | 0.65 / 4 / 1 |
| 표시 위치 / 각도 연결 시간상수 | 0.085초 / 0.12초 |
| 위치 재획득 확인 | 실제 수신 간격 × 0.65, 280~650ms |
| 큰 자세 변화 확인 | 수신 간격 × 0.7, 280~650ms |
| 좌우 전환 확인 | 수신 간격 × 0.9, 380~800ms |
| 전환 압축 시간 / 최소 가로 비율 | 0.24초 / 0.78 |
| 탐지·자세 점수 하한 | 0.25 (보정된 확률이라는 의미 아님) |
| 깊이 기준 수집 | 자세 있음 4개 이상·1.2초 / 없음 6개 이상·2.2초 |
| 깊이 기준 높이 변동 허용 | 최대/최소 1.08 이내 |
| 단발 높이 불연속 | 최근 중앙값과 log 비율 차이 0.12 초과 시 보류 |
| 지속 새 높이 확인 | 3개 이상·700ms / 자세 없음 1.4초 |
| 깊이 높이 필터 시간상수 / 배율 변화 상한 | 0.65초 / 초당 0.045 |
| 깊이 전체 크기 | 0.90~1.10 / 자세 없음 0.96~1.04 |
| 긴 중단의 깊이 기준 초기화 | 유효 위치 없이 5초 초과, 소켓의 lost 메시지 수신 여부와 무관 |
| 배치 자동 저장 디바운스 | 800ms |

실제 카메라 녹화로 확정한 수치가 아니라 이번 비교용 시작값이다. 카메라 줌·크롭 규칙이 바뀌는 외부 송신기는 새 stream_id로 알려야 한다. 프레임 크기·스트림·대상 변경은 기준을 초기화하고, 브라우저 창 크기는 초기화하지 않는다.

## 자동 검증

- `npm run build`: 실제 TypeScript 프로젝트 검사 및 프로덕션 빌드 통과. Three 청크 약 505KB에 대한 번들 크기 안내가 남는다.
- `npm test`: 7개 테스트 파일 통과. 등록된 37개 케이스에는 추가한 깊이·레이어·부위 이동 10개 케이스가 포함된다.
- `node --check server.cjs`, `git diff --check`: 통과.
- 서버 테스트는 메모리 SQLite를 사용해 계정 분리, middle 포함 순서 직렬화, 구형값 호환, 잘못된 저장 보존, 계정 불일치 거절을 검사한다.
- Chromium 자동화는 API·WebSocket을 모킹한다. 실제 계정·DB·급식 장치에 쓰지 않는다. 추적 대기·중단·복귀, 다른 소유자 입력 무시, 단발 이상치, 깊이 접근과 중심 유지, 레이어 편집·순서·새로고침 복원·실패 후 재시도, 부위 편집·저장·취소·렌더러 유지, WebGL 실패 시 이미지 표시, 움직임 줄이기, 1440/800/390px에서 가로 넘침을 확인했다. 페이지 런타임 오류는 0개다. FEED/RESET 호출이 없음을 확인했다.
- 브라우저 결과: [browser-check.json](browser-check.json). 1440×1000의 Headless Chromium 156, 소프트웨어 WebGL 비교 화면에서 1.5초 rAF 측정은 약 62.5회/초, 최대 간격 19ms였다. 발표 PC·실물 모바일의 GPU 성능 측정 결과는 아니다.

## 동일 입력 비교

`node scripts/compare-twin-tracking.mjs`로 재생성한다. 입력은 고정 1280×720, 400ms 패킷, 60Hz 표시의 합성 수평 수영이며 실제 어항 데이터가 아니다.

| 지표 | 기존 | 개선 |
|---|---:|---:|
| 정지 구간 표시 X의 RMS 오차 (정규화 좌표) | 0.002583 | 0.002396 |
| 느린 이동의 평균 표시 지연 | 908.7ms | 318.6ms |
| 빠른 이동의 평균 표시 지연 | 291.7ms | 287.9ms |

지연은 최신 샘플의 알려진 참값을 기준으로 계산했다. 영상의 샘플 사이 참궤적을 측정한 결과는 아니다. 깊이 구간의 표시 배율은 1.00→1.10으로 변했고 단발 높이 이상치는 보류했다. 실제 동작 영상에서의 개선율로 일반화하지 않는다.

## 남은 실제 환경 확인

실제 어항 원본 녹화·높이 시계열이 제공되지 않았다. 실측 저신뢰도·가림·지느러미 펼침 구간의 정확도, 실제 송신 주기와 네트워크 지연, 대표 사용자 그래픽별 연출 강도, 발표 PC와 실물 모바일 성능은 실제 자료로 추가 확인해야 한다.

특히 같은 자세로 지느러미만 천천히 펼치는 경우는 박스 높이만으로 접근과 구분되지 않을 수 있다. 검증된 펼침 분류기를 추가한 것은 아니다. 물리 어항의 외부 송신기가 bbox/frame_size를 누락하면 깊이를 사용할 수 없으며, 영상 크기를 추정해 만들어 넣지 않는다. 저장소의 개인 카메라 Python 경로는 이미 두 필드를 제공한다. 실제 거리·성장·활동량·건강 기록에 이 표시 보정값을 쓰지 않는다.
